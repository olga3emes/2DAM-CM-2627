# Servicios de computación en la nube de AWS

De mayor a menor nivel de abstracción y personalización, los servicios de computación en la nube de AWS incluyen:

EC2: "Los servidores - como si me creo una MV". Elastic Compute Cloud, es un servicio de computación en la nube que permite a los usuarios ejecutar instancias de servidores virtuales en la infraestructura de AWS.

ECS: "Contenedores - como si me creo un docker en la nube". Amazon Elastic Container Service (ECS) es un servicio de orquestación de contenedores que permite a los usuarios ejecutar y administrar aplicaciones en contenedores de manera escalable y segura.

EKS: "Kubernetes - como si me creo un cluster de docker en la nube". Amazon Elastic Kubernetes Service (EKS) es un servicio administrado de Kubernetes que facilita la implementación, administración y escalado de aplicaciones en contenedores utilizando Kubernetes en la nube de AWS.

Amazon LightSail: "Servidores sencillos - como si me creo un servidor en la nube sin complicaciones". Amazon Lightsail es un servicio de computación en la nube que proporciona una forma sencilla de lanzar y administrar servidores virtuales, bases de datos y aplicaciones web con una interfaz fácil de usar y precios predecibles.

Amazon Beanstalk: "Despliegue sencillo - como si me creo un script que se ejecuta en la nube y me despliega mi aplicación". AWS Elastic Beanstalk es un servicio que facilita el despliegue y escalado de aplicaciones web y servicios desarrollados en varios lenguajes de programación, gestionando automáticamente la infraestructura subyacente.

Lambda: "Funciones(procedimientos almacenados) - como si me creo un script que se ejecuta en la nube". AWS Lambda es un servicio de computación sin servidor que permite a los usuarios ejecutar código en respuesta a eventos sin tener que aprovisionar o administrar servidores.

Fargate: "Contenedores sin servidor - como si me creo un docker en la nube sin tener que gestionar servidores". AWS Fargate es un servicio de computación sin servidor para contenedores que permite a los usuarios ejecutar aplicaciones en contenedores sin tener que administrar la infraestructura subyacente, proporcionando escalabilidad automática y facturación basada en el uso.

EBS: "Discos duros - como si me creo un disco duro en la nube". Amazon Elastic Block Store (EBS) es un servicio de almacenamiento en bloque que proporciona volúmenes de almacenamiento persistente para instancias EC2, permitiendo a los usuarios almacenar y acceder a datos de manera confiable y escalable.

AMI: "Imagen de máquina - como si me creo un disco duro con un SO y lo guardo en la nube". Amazon Machine Image (AMI) es una plantilla que contiene una configuración de software (sistema operativo, aplicaciones y configuraciones) que se utiliza para crear instancias EC2 en la nube de AWS.

EC2 Image Builder: "Creación de imágenes - como si me creo un script que me crea un disco duro con un SO y lo guarda en la nube". Amazon EC2 Image Builder es un servicio que facilita la creación, prueba y despliegue de imágenes de máquina personalizadas (AMIs) para instancias EC2, automatizando el proceso de construcción y mantenimiento de imágenes seguras y actualizadas.

AWS Compute Optimizer: "Optimización de recursos - como si me creo un script que me analiza el rendimiento de mis servidores y me dice cómo optimizarlos". AWS Compute Optimizer es un servicio que utiliza aprendizaje automático para analizar el uso de recursos de las instancias EC2 y recomendar configuraciones óptimas para mejorar el rendimiento y reducir costos.

¿Qué sucede si tiene varias instancias que deben usar el mismo almacenamiento?
Amazon EFS y Amazon FSx para Windows File Server: ambos cumplen los requisitos

Amazon EFS: "Disco duro compartido para LINUX - como si me creo un disco duro en la nube y lo comparto entre varios servidores". Amazon Elastic File System (EFS) es un servicio de almacenamiento de archivos en la nube que permite a los usuarios crear sistemas de archivos escalables y compartidos que pueden ser montados por múltiples instancias EC2 simultáneamente.

Amazon FSx para Windows File Server: "Disco duro compartido para WINDOWS - como si me creo un disco duro en la nube y lo comparto entre varios servidores". Amazon FSx for Windows File Server es un servicio de almacenamiento de archivos en la nube que proporciona sistemas de archivos totalmente administrados y compatibles con Windows, permitiendo a los usuarios compartir archivos entre múltiples instancias EC2 que ejecutan Windows.

# Amazon EC2 

## ¿Qué es Amazon EC2?

**EC2 (Elastic Compute Cloud)** es el servicio de AWS que permite crear y utilizar servidores virtuales en la nube.

Podemos imaginar EC2 como un **ordenador que alquilamos por Internet** y que podemos encender, apagar o configurar cuando lo necesitemos.

Con EC2 podemos:

- Ejecutar aplicaciones web.
- Instalar bases de datos.
- Crear servidores de pruebas.
- Alojar páginas web.
- Ejecutar programas corporativos.

En lugar de comprar servidores físicos, utilizamos servidores virtuales que AWS proporciona bajo demanda.

---

# ¿Por qué es importante EC2?

Antes del cloud, una empresa debía:

- Comprar servidores.
- Instalar hardware.
- Mantener equipos.
- Ampliar capacidad manualmente.

Con EC2 podemos crear un servidor en pocos minutos y pagar únicamente por el tiempo que lo utilizamos.

---

# Conceptos principales de EC2

## Instancia

Una instancia es un servidor virtual creado en EC2.

Ejemplos:

- Servidor Linux.
- Servidor Windows.
- Servidor para una aplicación web.
- Servidor para una base de datos.

Cuando hablamos de EC2 normalmente hablamos de instancias.

---

## AMI (Amazon Machine Image)

Una AMI es una plantilla utilizada para crear instancias.

Incluye:

- Sistema operativo.
- Configuración básica.
- Software preinstalado.

Ejemplos:

- Ubuntu.
- Amazon Linux.
- Windows Server.
- Red Hat Enterprise Linux.

Podemos imaginar una AMI como la imagen de instalación de un ordenador.

---

## Tipo de instancia

Determina la potencia del servidor.

Define:

- CPU.
- Memoria RAM.
- Red.
- Rendimiento.

Ejemplos:

```PlainText
t3.micro
m5.large
c5.xlarge
```

Cuanto más recursos tenga, mayor será el coste.

---

# Ciclo de vida de una instancia

Una instancia puede estar en varios estados:

```PlainText
Lanzar
   ↓
Ejecutándose
   ↓
Detenida
   ↓
Iniciada nuevamente
   ↓
Terminada
```

Cuando una instancia se termina, deja de existir.

---

# Almacenamiento en EC2

## EBS (Elastic Block Store)

EBS funciona como el disco duro de la instancia.

Permite guardar:

- Sistema operativo.
- Aplicaciones.
- Archivos.
- Bases de datos.

Aunque apaguemos la máquina, los datos pueden mantenerse en el volumen EBS.

---

## Instance Store

Es un almacenamiento temporal.

Ventajas:

- Muy rápido.

Desventaja:

- Si la instancia desaparece, los datos se pierden.

Por eso se utiliza únicamente para información temporal.

---

# Redes en EC2

## Dirección IP pública

Permite acceder al servidor desde Internet.

Ejemplo:

```PlainText
54.21.10.100
```

---

## Dirección IP privada

Se utiliza para la comunicación interna dentro de AWS.

Ejemplo:

```PlainText
10.0.1.15
```

---

## VPC

Una VPC (Virtual Private Cloud) es una red privada dentro de AWS.

Las instancias EC2 normalmente se ejecutan dentro de una VPC.

Podemos considerarla la red de nuestra empresa en la nube.

---

# Seguridad en EC2

## Security Groups

Los Security Groups funcionan como un firewall.

Permiten decidir:

- Qué tráfico entra.
- Qué tráfico sale.

Ejemplo:

```PlainText
Puerto 80 → Permitido
Puerto 443 → Permitido
Puerto 22 → Solo administradores
```

Es una de las medidas de seguridad más importantes en AWS.

---

## Par de claves (Key Pair)

En Linux normalmente no accedemos con contraseña.

Se utiliza:

- Clave pública.
- Clave privada.

Al crear la instancia AWS genera estas claves para conectarnos mediante SSH.

---

# Escalabilidad

Una de las principales ventajas de EC2.

## Escalado vertical

Consiste en aumentar la potencia de una máquina.

Ejemplo:

```PlainText
t3.micro → t3.large
```

Más CPU y más memoria.

---

## Escalado horizontal

Consiste en añadir más servidores.

Ejemplo:

```PlainText
Servidor 1
Servidor 2
Servidor 3
```

Permite gestionar más usuarios simultáneamente.

---

# Alta disponibilidad

## Load Balancer

Distribuye las peticiones entre varios servidores.

Ejemplo:

```PlainText
Usuarios
   ↓
Load Balancer
   ↓
EC2-1
EC2-2
EC2-3
```

Si un servidor falla, los demás siguen prestando servicio.

---

## Multi\-AZ

Las instancias pueden distribuirse entre varias zonas de disponibilidad.

Esto mejora la tolerancia a fallos.

---

# Integración con otros servicios AWS

## EC2 \+ S3

Permite almacenar archivos en S3 mientras la aplicación se ejecuta en EC2.

---

## EC2 \+ RDS

La aplicación se ejecuta en EC2 y la base de datos en RDS.

Es una arquitectura muy habitual.

---

## EC2 \+ IAM

IAM permite controlar quién puede administrar las instancias.

---

# Casos reales de uso

## Página web corporativa

- Servidor web en EC2.
- Archivos multimedia en S3.

---

## Tienda online

- Aplicación web en EC2.
- Base de datos en RDS.
- Balanceador de carga para repartir usuarios.

---

## Entorno de desarrollo

Los desarrolladores crean instancias temporales para realizar pruebas sin comprar servidores físicos.

---

# Buenas prácticas para trabajo real

✅ Aplicar Security Groups restrictivos.

✅ Utilizar IAM para gestionar accesos.

✅ Realizar copias de seguridad mediante snapshots.

✅ Utilizar varias instancias para aplicaciones importantes.

✅ Apagar instancias que no se estén utilizando para ahorrar costes.

✅ Mantener actualizado el sistema operativo.
