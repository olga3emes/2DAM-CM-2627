## ¿Qué es Amazon IAM?

**IAM (Identity and Access Management)** es el servicio de AWS que permite controlar quién puede acceder a los recursos y qué acciones puede realizar.

Podemos imaginar IAM como el **sistema de usuarios y permisos de AWS**.

Gracias a IAM podemos:

- Crear usuarios.
- Crear grupos.
- Asignar permisos.
- Controlar el acceso a servicios AWS.
- Mejorar la seguridad de la cuenta.

Sin IAM, cualquier persona con acceso a la cuenta podría modificar o eliminar recursos críticos.

---

# ¿Por qué es importante IAM?

Cuando una empresa utiliza AWS suele tener:

- Administradores.
- Desarrolladores.
- Técnicos de sistemas.
- Analistas de datos.

No todos necesitan los mismos permisos.

Por ejemplo:

- Un desarrollador puede crear máquinas virtuales.
- Un analista puede consultar datos.
- Un administrador puede gestionar toda la infraestructura.

IAM permite aplicar esta separación de responsabilidades.

---

# Conceptos principales de IAM

## Usuario (User)

Un usuario representa una persona o aplicación.

Ejemplos:

- Ana (administradora).
- Carlos (desarrollador).
- Aplicación Web.

Cada usuario puede disponer de:

- Nombre de usuario.
- Contraseña.
- Claves de acceso (Access Keys).
- Permisos.

---

## Grupo (Group)

Un grupo es un conjunto de usuarios que comparten permisos.

Ejemplo:

```PlainText
Grupo: Desarrolladores
 ├── Ana
 ├── Juan
 └── María
```

Si añadimos permisos al grupo, todos los usuarios los heredan.

Esto simplifica enormemente la administración.

---

## Política (Policy)

Una Policy es un documento JSON que define permisos.

Indica:

- Qué acciones están permitidas.
- Sobre qué recursos.
- En qué condiciones.

Ejemplo conceptual:

```PlainText
Permitir leer archivos de S3
```

Las políticas son el elemento principal para controlar el acceso en AWS.

---

## Rol (Role)

Un rol es una identidad temporal que puede ser utilizada por:

- Usuarios.
- Aplicaciones.
- Servicios AWS.

Ejemplo:

Una función Lambda necesita acceder a un bucket S3.

En lugar de guardar usuario y contraseña, se le asigna un rol con los permisos necesarios.

Es una práctica mucho más segura.

# Autenticación y autorización

## Autenticación

Responde a la pregunta:

**¿Quién eres?**

Ejemplos:

- Usuario y contraseña.
- Claves de acceso.
- MFA.

---

## Autorización

Responde a la pregunta:

**¿Qué puedes hacer?**

Ejemplos:

- Leer objetos en S3.
- Crear instancias EC2.
- Consultar una base de datos.

IAM se encarga principalmente de esta parte.

---

# Principio de mínimo privilegio

Una de las normas más importantes de AWS.

Consiste en conceder únicamente los permisos estrictamente necesarios.

Ejemplo:

❌ Permitir acceso completo a AWS.

✅ Permitir únicamente leer un bucket concreto.

Esto reduce errores y aumenta la seguridad.

---

# Seguridad en IAM

## Contraseña segura

AWS permite definir políticas de contraseñas.

Por ejemplo:

- Longitud mínima.
- Números.
- Mayúsculas.
- Caracteres especiales.

---

## MFA (Multi\-Factor Authentication)

Añade una segunda capa de seguridad.

Además de la contraseña, el usuario debe introducir un código temporal.

Ejemplos:

- Google Authenticator.
- Microsoft Authenticator.
- Llaves físicas de seguridad.

Aunque alguien robe la contraseña, no podrá acceder fácilmente.

---

## Root User

Cuando se crea una cuenta AWS aparece el usuario Root.

Este usuario tiene control total sobre la cuenta.

Buenas prácticas:

- No utilizarlo diariamente.
- Activar MFA.
- Crear usuarios IAM para el trabajo habitual.

# IAM y otros servicios AWS

## IAM \+ S3

Permite decidir:

- Quién puede subir archivos.
- Quién puede descargarlos.
- Quién puede borrarlos.

---

## IAM \+ EC2

Permite controlar:

- Creación de máquinas virtuales.
- Parada y arranque.
- Eliminación de instancias.

---

## IAM \+ Lambda

# Casos reales de uso

## Empresa pequeña

- Administrador → acceso completo.
- Empleados → acceso limitado.

---

## Equipo de desarrollo

- Desarrolladores → EC2 y Lambda.
- Analistas → Athena y S3.
- Sistemas → todos los recursos.

---

## Aplicaciones automáticas

Una aplicación puede utilizar un rol para acceder a una base de datos o a un bucket S3 sin almacenar credenciales.

# Buenas prácticas para trabajo real

✅ Utilizar grupos para gestionar permisos.

✅ Aplicar el principio de mínimo privilegio.

✅ Activar MFA.

✅ No trabajar habitualmente con la cuenta Root.

✅ Utilizar roles para aplicaciones y servicios.

✅ Revisar periódicamente los permisos.
