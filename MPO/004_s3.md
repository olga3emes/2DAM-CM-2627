# Amazon S3 (Explicado para FP)

## ¿Qué es Amazon S3?

**Amazon S3 (Simple Storage Service)** es un servicio de AWS que permite almacenar archivos en la nube.

Piensa en S3 como un **disco duro gigante en Internet** donde podemos guardar:

- Fotos
- Vídeos
- Copias de seguridad
- Documentos
- Archivos de aplicaciones
- Datos para Big Data e Inteligencia Artificial

La principal ventaja es que no tenemos que preocuparnos por comprar discos duros ni servidores. AWS se encarga de mantener la infraestructura.

---

## ¿Cómo organiza S3 la información?

### Bucket

Un **bucket** es un contenedor donde almacenamos archivos.

Podemos compararlo con una carpeta principal.

Ejemplo:

```Sql
Bucket: empresa-backups
```

Dentro del bucket pueden existir miles o millones de archivos.

---

### Objeto (Object)

Cada archivo almacenado en S3 se llama **objeto**.

Ejemplos:

```Sql
foto.jpg
factura.pdf
backup.zip
video.mp4
```

Cada objeto tiene:

- Nombre (Key)
- Contenido
- Fecha de creación
- Tamaño
- Otros metadatos

---

### Key

La **Key** identifica de forma única un objeto dentro de un bucket.

Ejemplo:

```Sql
clientes/2026/factura1.pdf
```

Aunque parezca una carpeta, realmente es solo una ruta lógica.

---

# Ventajas principales de S3

## Escalabilidad

No hay que ampliar discos manualmente.

Si hoy guardamos:

- 100 MB
- 10 GB
- 100 TB

S3 sigue funcionando exactamente igual.

---

## Alta durabilidad

AWS garantiza una durabilidad del:

**99,999999999% (11 nueves)**

Esto significa que la probabilidad de perder un archivo es extremadamente baja.

Para conseguirlo, AWS guarda múltiples copias de nuestros datos en varios centros de datos.

---

## Alta disponibilidad

Nuestros datos están accesibles prácticamente todo el tiempo.

Aunque falle un servidor o un centro de datos, S3 sigue funcionando.

---

## Pago por uso

Solo pagamos por:

- El almacenamiento utilizado.
- Las peticiones realizadas.
- Los datos transferidos.

No es necesario comprar infraestructura.

---

# Clases de almacenamiento

No todos los archivos se utilizan igual.

Por eso AWS ofrece varias clases.

## S3 Standard

Para archivos utilizados frecuentemente.

Ejemplos:

- Imágenes de una web.
- Archivos de una aplicación.
- Vídeos visualizados diariamente.

Es la opción más rápida.

---

## S3 Standard\-IA

(IA = Infrequent Access)

Para archivos que se consultan pocas veces.

Ejemplos:

- Informes antiguos.
- Backups recientes.

Más barato que Standard.

---

## S3 Glacier

Diseñado para archivado.

Ejemplos:

- Facturas de años anteriores.
- Expedientes históricos.
- Copias legales.

Es muy barato, pero recuperar datos puede tardar minutos u horas.

---

## Glacier Deep Archive

La opción más económica.

Se utiliza para almacenar información durante años sin necesidad de acceder a ella habitualmente.

Por ejemplo:

- Copias de seguridad legales.
- Documentación obligatoria por normativa.

---

# Seguridad en S3

## Control de acceso

No todo el mundo puede acceder a nuestros archivos.

Podemos definir:

- Quién puede leer.
- Quién puede subir archivos.
- Quién puede borrar información.

Esto se gestiona mediante IAM y Bucket Policies.

---

## Cifrado

El cifrado convierte la información en datos ilegibles para personas no autorizadas.

Existen dos momentos clave:

### En tránsito

Cuando los datos viajan por Internet.

Se utiliza HTTPS.

---

### En reposo

Cuando los datos están almacenados en AWS.

S3 puede cifrarlos automáticamente.

---

## Bloqueo de acceso público

AWS recomienda bloquear el acceso público por defecto.

Así evitamos errores de configuración que expongan información sensible.

---

# Versionado

El versionado permite guardar varias versiones del mismo archivo.

Ejemplo:

1. Subimos `proyecto.docx`
2. Lo modificamos
3. Lo volvemos a subir

S3 conserva ambas versiones.

Si cometemos un error, podemos recuperar una versión anterior.

---

# Replicación

La replicación consiste en copiar automáticamente los archivos a otra ubicación.

## Misma región (SRR)

La copia se crea dentro de la misma región AWS.

Ejemplo:

```Sql
Madrid → Madrid
```

---

## Distinta región (CRR)

La copia se crea en otra región.

Ejemplo:

```Sql
Madrid → Frankfurt
```

Esto mejora la recuperación ante desastres.

---

# Lifecycle (Ciclo de vida)

Permite automatizar la gestión de los archivos.

Por ejemplo:

- Después de 30 días → mover a Standard\-IA.
- Después de 180 días → mover a Glacier.
- Después de 5 años → eliminar.

Así reducimos costes automáticamente.

---

# Integración con otros servicios AWS

## CloudFront

Permite distribuir archivos rápidamente por todo el mundo.

Ejemplo:

- Una web almacena imágenes en S3.
- CloudFront las entrega desde servidores cercanos al usuario.

---

## Lambda

Ejecuta código automáticamente cuando ocurre un evento.

Ejemplo:

```Sql
Un usuario sube una foto
↓
Lambda la redimensiona automáticamente
↓
Se guarda la versión reducida
```

---

## Athena

Permite consultar archivos almacenados en S3 usando SQL.

Ejemplo:

```Sql
SELECT * FROM ventas
WHERE provincia='Sevilla';
```

Sin necesidad de base de datos.

# Casos reales de uso

## Sitio web estático

Una página HTML puede almacenarse directamente en S3.

Ejemplo:

- HTML
- CSS
- JavaScript
- Imágenes

Todo alojado en AWS sin servidor web tradicional.

---

## Copias de seguridad

Muchas empresas utilizan S3 para guardar:

- Backups de bases de datos.
- Máquinas virtuales.
- Documentación empresarial.

---

## Data Lake

Grandes empresas almacenan enormes cantidades de datos en S3 para analizarlos posteriormente.

Por ejemplo:

- Amazon
- Netflix
- Airbnb
